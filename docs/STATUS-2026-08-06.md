## What DraftHQ is

A **premium draft-night companion**, not a Sleeper/ESPN replacement. Commissioners
import their existing league, run a far better draft night in DraftHQ, then go
back to their platform for the season.

Every product decision should answer: *"why would a commissioner run draft night
here instead of in their platform's built-in draft?"* Optimize for: frictionless
import, an unforgettable event, and easy export back. Do **not** build league
history, standings, or year-round engagement.

### `590487b` — Owners get their own dashboard

The league command center was entirely commissioner-shaped. An owner saw
**"33% READY"**, "4 OPEN ITEMS", and a panel titled *"Next Commissioner Action"*
— a checklist of work they cannot do. When setup was incomplete, `primaryAction`
fell through to `null`, so they got **no button at all**.

For `!workspace.canManage`:

  (Draft Scheduled / Draft Live / Draft Paused / Draft Complete / Date TBD /
  Draft Not Created)
- **"Your Team"** panel replaces "Next Commissioner Action" — team, assigned
  status, draft slot, rounds, plus a plain-English note when the slot or
  assignment is still out of their hands
- **There is always a button.** A draft existing is enough (the lobby handles
  pre-draft), so Enter/Join Draft Room shows regardless of readiness, falling
  back to the league team list when no draft exists. Secondary action goes to
  the existing `/leagues/[slug]/my-team` page

- Hero metrics become Draft Status / Your Pick / Pick Clock / League members

`src/lib/ownerDashboard.ts` derives the view as **pure logic**, covered by
`tests/unit/ownerDashboard.test.ts` (9 tests). Keep new owner-facing branching
there rather than inline in the component. Draft slot comes from
`getLeagueTeamDraftSlot()` reading `league_team_seasons`, which league members
can already select under existing RLS — **no migration**. Fails soft to "TBD".

### `89fff8e` — The `league-assets` bucket never existed

`uploadLeagueAsset` wrapped the storage call in a `try` whose `catch` read
*"storage bucket not configured — fall through."* It was right. **Every league
logo upload had been failing silently**, taking a fallback that canvas-resized
to **256px**, base64-encoded, and stored the data URL in `leagues.logo_url`.

That is the real cause of blurry logos on the TV — not small source images. The
one existing league carried a **206KB** data URL shipped on every workspace load.

- Bucket created with public read, 4MB limit, image MIME allowlist, and
  commissioner-scoped insert/update/delete via `is_league_commissioner()`
- Path is now `{leagueId}/{type}.{ext}` — the stable UUID prefix the old TODO
  called for, so RLS can scope on it. **Closes security/C2.**
- Uploads throw instead of degrading silently
- Stale siblings cleared (`.webp` over `.png` would strand the old object);
  URL cache-busted now that the path is stable
- `compressImage` deleted — `MAX_FILE_BYTES` already rejects >4MB at selection
  time, exactly matching the bucket limit

> ⚠️ **Existing logos are not recoverable by migration.** The stored data URL is
> already downsampled to 256px; the original file is gone. Each commissioner must
> **re-upload their logo once**. This is also the only real end-to-end test of
> the change — it needs a signed-in commissioner.

## Previously shipped

### Draft grading (`src/lib/draftGrading.ts`)
Per-pick 0–100 scores and overall team grades, judged on what was knowable
**at the time of the pick** — the board and each roster are replayed pick by pick.

Five weighted factors: **value vs market 40%**, **team need 20%**, **positional
scarcity 15%**, **player quality 15%**, **roster construction 10%**.
Team grade = 70% round-weighted picks + 20% final construction + 10% strategy.
Calibrated so an ordinary draft lands **C+/B-**, guarded by
`tests/unit/draftGradingCalibration.test.ts` which simulates a full draft.

Three bugs were found by simulation and fixed — **do not reintroduce**:
1. K/DST are ranked ~290–320 overall but drafted in the last two rounds. Judged
   against overall rank that reads as a 150-pick reach. Value is now skipped for
   them unless real ADP exists.
2. Quality used overall rank, punishing every late pick for being late. Now
   measured **within position**.
3. Need counted unfilled K/DST slots as pressing all draft, while construction
   penalized drafting them early — the engine contradicted itself. They only
   become pressing in the final rounds.

UI: **Draft Grades** board view (complete drafts only) with per-team summaries,
strengths/concerns, and every pick's score + explanation. Awards ceremony finale
shows the real grades.

### Data pipeline
- ESPN **ADP** + **projected points** captured in the rankings sync. ESPN
  flattens ADP to a constant once a season ends — the sync detects the
  degenerate spread and discards it rather than feeding the grader a fake signal.
- **Sleeper `roster_positions` is parsed** (it was fetched and thrown away —
  only `.length` was used). Gives real starting lineups, FLEX/SUPER_FLEX, bench
  size, and scoring format on imported drafts. TE premium is detected and warned
  about since DraftHQ can't model it.

### Draft night experience
TV/broadcast mode, awards ceremony (one award per screen, music, league logos),
landmine videos, walk-up resume/restart mode, draft-order race lottery,
lobby presence + volume, mobile owner audit, Draft Complete modal.

## Known gaps and limitations

**Data the grader cannot use** (honest limits, not omissions):
- No floor/ceiling/risk/role data — "upside" is inferred from rank and round
- TE premium isn't a supported scoring type
- Keeper/dynasty not in the schema
- Projections are PPR-scored from ESPN's default league regardless of format

**AI announcers are disabled everywhere** (`isAiAnnouncerEnabled()` in
`src/lib/speech.ts`). All plumbing is intact — OpenAI personas, BYO-ElevenLabs
with per-request keys, storage-cached clips, device-TTS fallback. Flip
`NEXT_PUBLIC_AI_ANNOUNCER_ENABLED=true` to relaunch.

**Manually-created drafts still have no starting lineup** — every `min` defaults
to 0. The grader infers a standard lineup and labels it as assumed. Sleeper
imports are exact.

**Draft schedule timezone is wrong for non-local zones.** Both
`TeamSetupForm` and the new Create Draft modal build the ISO timestamp with
`new Date(\`${date}T${time}\`).toISOString()` — the **browser's** local zone —
while the timezone dropdown is stored separately and never shifts the instant.
A commissioner in Chicago selecting `America/New_York` gets a time one hour off.
Pre-existing; the new field inherits it rather than diverging.

**Stabilization leftovers**: 8 deferred lint errors, no rate limiting on public
endpoints, Spotify tokens in localStorage. (The `league-assets` RLS item is now
resolved.)

## Architecture notes worth knowing

**Audio is the most fragile subsystem.** It was audited and hardened; the
invariants matter:
- Playback position is **derived**, never stored — every client computes the same
  answer from pick timestamps, which is why walk-up music stays in sync
- One `walkUpDelayRef` timeout slot; every transition clears it before scheduling
- Reveal and landmine ownership is enforced at **fire time** inside delayed
  closures (`revealActiveRef`, `landmineActiveRef`), not just at schedule time
- `WalkUpPlayer.play()` reloads from the top — never call it to "resume"

**Grading is cached** against `picks · rankings · scoring · rounds` and only
computed when the grades view or ceremony is open. It walks every pick against
the whole board.

**Draft correctness lives in Supabase/Postgres.** React displays state; it does
not enforce draft rules. Don't use localStorage as authoritative draft state.

**`update_draft_extras` is recreated by several migrations.** Adding a parameter
means dropping and recreating the whole function and updating the `revoke`/`grant`
signatures. The client always sends every parameter, so code and migration must
deploy together. Prefer a **post-create update call** over a new RPC parameter
when you can — that's how the Create Draft date field avoided a migration.

**Storage path conventions are load-bearing.** RLS policies parse the object name
with `storage.foldername(name)[1]::uuid`, so the first path segment must be the
owning entity's UUID. `league-assets` → `{leagueId}/{type}.{ext}`; draft team
assets → `{draftId}/{teamId}/...`; draft audio → `{draftId}/...`. Changing a path
format without changing its policy silently breaks writes.

**Silent fallbacks hide outages.** Two bugs this session came from `catch {}`
blocks that degraded quietly — a missing storage bucket masked for weeks, and a
downsampled logo nobody chose. Prefer failing loudly where a user can see it.
